PANDUAN HANDOFF DEPLOYMENT SERVER PRODUKSI AMI
==============================================

Dokumen ini adalah handoff untuk tim yang menyiapkan dan mengoperasikan deployment
produksi Audit Mutu Internal. Ikuti juga docs/DEPLOYMENT_NON_DOCKER.md untuk
konfigurasi web server lengkap, termasuk PHP-FPM, Nginx atau Apache, document root,
alias atau symlink public uploads, dan aturan penolakan akses. Dokumen ini tidak
menggantikan panduan tersebut.

Batas proses sangat tegas: run-local-php.sh di root repository hanya kemudahan
development. Script itu memuat .env lokal, lalu menjalankan php -S pada 127.0.0.1:8000.
Script tersebut BUKAN process manager, BUKAN web server produksi, dan TIDAK BOLEH
digunakan untuk menjalankan AMI di production. Production harus memakai web server
dan PHP-FPM sesuai docs/DEPLOYMENT_NON_DOCKER.md.

CHECKLIST SEBELUM DEPLOYMENT
============================

[ ] Gunakan server yang memenuhi kebutuhan OS, PHP 8.3, PHP-FPM, MySQL 8.0 atau
    MariaDB 10.11+, Composer 2.x, dan web server yang didukung.
[ ] Pastikan ekstensi PHP aktif: mysqli, mbstring, xml, zip, gd, curl, intl,
    bcmath, dan fileinfo. Periksa dengan:

    php -v
    php -m | sort

[ ] Gunakan tag atau commit yang sudah direview. Jangan deploy branch kerja yang
    masih berubah.
[ ] Pastikan tidak ada .env, credential, private key, dump database, backup, atau
    log di Git maupun di document root.
[ ] Pastikan private storage dan log berada di luar webroot.
[ ] Buat backup database dan APP_PRIVATE_STORAGE_PATH sebelum deployment atau
    perubahan schema.
[ ] Simpan release sebelumnya agar rollback dapat dilakukan tanpa membangun ulang
    artifact di saat insiden.

KONFIGURASI ENVIRONMENT PRODUKSI
=================================

Set environment pada pool PHP-FPM atau mekanisme environment server yang aman,
bukan dengan commit .env ke repository. Semua nilai di bawah adalah contoh dengan
placeholder. Ganti setiap placeholder melalui secret manager atau prosedur rahasia
deployment.

    CI_ENV=production
    APP_BASE_URL=https://<hostname-produksi>/
    APP_ENCRYPTION_KEY=<secret-acak-persisten-minimal-64-karakter>
    APP_COOKIE_SECURE=true
    APP_LOG_THRESHOLD=1

    DB_HOST=<hostname-atau-ip-database-produksi>
    DB_USERNAME=<user-database-produksi>
    DB_PASSWORD=<password-database-produksi>
    DB_DATABASE=<nama-database-produksi>

    APP_PRIVATE_STORAGE_PATH=/var/ami-storage/private
    APP_PUBLIC_UPLOADS_PATH=/var/ami-storage/public_uploads
    APP_LOG_PATH=/var/log/ami/
    SPMI_EVIDENCE_STORAGE_BACKEND=local

APP_BASE_URL wajib HTTPS dan diakhiri slash. APP_ENCRYPTION_KEY harus dibuat khusus
untuk deployment ini, disimpan tetap, dan tidak boleh memakai
local-development-only-key atau credential Docker development.

APP_PRIVATE_STORAGE_PATH wajib di luar webroot. APP_PUBLIC_UPLOADS_PATH boleh memakai
folder eksternal seperti contoh di atas. Alternatif defaultnya adalah uploads/ di
document root aplikasi jika APP_PUBLIC_UPLOADS_PATH tidak diset. Jika memakai path
eksternal, konfigurasi web server harus hanya mengekspos uploads/profil sesuai
allowlist yang dijelaskan dalam docs/DEPLOYMENT_NON_DOCKER.md. Jangan mengekspos
kategori private atau path public lain.

Backend bukti production yang dipakai di sini adalah local. Jika deployment memang
menggunakan Google Drive, isi hanya konfigurasi production yang telah direview:

    SPMI_EVIDENCE_STORAGE_BACKEND=google_drive
    GOOGLE_DRIVE_AUTH_MODE=service_account
    GOOGLE_DRIVE_EVIDENCE_FOLDER_ID=<id-folder-drive>
    GOOGLE_DRIVE_SERVICE_ACCOUNT_JSON_PATH=<path-credential-di-luar-webroot>

Jangan memakai OAuth Google Drive di production. Brevo bersifat opsional dan hanya
diisi bila reset password akan digunakan:

    BREVO_API_KEY=<secret-api-brevo>
    MAIL_FROM_ADDRESS=<alamat-pengirim-terverifikasi>
    MAIL_FROM_NAME=<nama-pengirim>

Simpan file credential Drive dan secret Brevo di luar repository dan webroot.

RELEASE DAN DEPENDENCY
======================

Jalankan dari direktori release yang sudah berisi tag atau commit review. Sesuaikan
path dengan layout server, tanpa mengubah document root menjadi private storage.

    cd /var/www/<nama-aplikasi>
    composer install --no-dev --prefer-dist --no-interaction --optimize-autoloader
    npm ci
    npm run build

Pastikan composer.lock dan package-lock.json ikut release yang direview. Jangan
menggunakan run-local-php.sh sebagai pengganti PHP-FPM.

STRUKTUR DIREKTORI PRODUKSI
===========================

    /var/www/<nama-aplikasi>/
    /var/ami-storage/private/
    /var/ami-storage/public_uploads/profil/
    /var/log/ami/
    /var/www/<nama-aplikasi>/application/cache/sessions/

Private storage harus memiliki kategori berikut:

    audit_evidence
    bukti_auditor
    instrumen
    penetapan
    ppepp_documents
    rtm_photos
    spmi_source
    tmp
    user_photos

Buat direktori dan atur kepemilikan serta mode berikut. Ganti
/var/www/<nama-aplikasi> hanya bila document root deployment berbeda.

    sudo mkdir -p /var/ami-storage/private/{audit_evidence,bukti_auditor,instrumen,penetapan,ppepp_documents,rtm_photos,spmi_source,tmp,user_photos}
    sudo mkdir -p /var/ami-storage/public_uploads/profil
    sudo mkdir -p /var/log/ami
    sudo mkdir -p /var/www/<nama-aplikasi>/application/cache/sessions
    sudo mkdir -p /var/www/<nama-aplikasi>/uploads/profil

    sudo chown -R www-data:www-data /var/ami-storage
    sudo chown -R www-data:www-data /var/log/ami
    sudo chown -R www-data:www-data /var/www/<nama-aplikasi>/application/cache/sessions
    sudo chown -R www-data:www-data /var/www/<nama-aplikasi>/uploads

    sudo chmod -R 0700 /var/ami-storage/private
    sudo chmod -R 0775 /var/ami-storage/public_uploads
    sudo chmod -R 0750 /var/log/ami
    sudo chmod -R 0700 /var/www/<nama-aplikasi>/application/cache/sessions
    sudo chmod 0775 /var/www/<nama-aplikasi>/uploads/profil

Jangan memberi akses web langsung ke /var/ami-storage/private atau /var/log/ami.
Public upload hanya boleh melayani file profil yang diizinkan aplikasi. Ikuti blok
allowlist dan penolakan executable di docs/DEPLOYMENT_NON_DOCKER.md.

MIGRASI DATABASE DENGAN AMAN
============================

Untuk database existing, backup database, triggers, routines, events, dan seluruh
APP_PRIVATE_STORAGE_PATH sebelum migration. Terapkan raw SQL di migrations/ secara
numerik, satu file tiap langkah, dan berhenti pada error pertama. Jangan memakai
CodeIgniter migration library, jangan menonaktifkan foreign key checks, dan jangan
menjalankan blok DOWN historis.

Database baru memakai database_schema.sql. Jangan menjalankan migration individual
setelah schema bootstrap baru diimport. Database lama mengikuti daftar dan aturan
urutan pada docs/DEPLOYMENT_NON_DOCKER.md. Catat migration terakhir yang berhasil.

START, RELOAD, DAN RESTART SERVICE
===================================

Jangan menebak atau membuat nama service aplikasi. Gunakan nama unit yang terdaftar
di server. Contoh pemeriksaan referensi:

    systemctl list-units --type=service | grep -E 'php.*fpm|nginx|apache'
    systemctl status php8.3-fpm
    sudo nginx -t
    sudo systemctl reload nginx

Jika konfigurasi PHP-FPM berubah, gunakan unit PHP-FPM yang benar di server, lalu
periksa statusnya kembali. Reload atau restart hanya dilakukan setelah configuration
test berhasil dan sesuai prosedur perubahan tim.

Periksa endpoint HTTPS production, bukan endpoint local runner:

    curl -i https://<hostname-produksi>/index.php/auth

Periksa path, ownership, dan mode tanpa menampilkan isi credential:

    namei -l /var/ami-storage/private
    namei -l /var/ami-storage/private/audit_evidence
    namei -l /var/ami-storage/public_uploads/profil
    namei -l /var/log/ami

Smoke test login, upload dan download sesuai role, import, laporan, serta akses
yang seharusnya ditolak sebelum membuka traffic lebih luas. Pastikan private file
tidak dapat diambil melalui URL publik.

CATATAN KEAMANAN DAN ROLLBACK
=============================

Backup database dan APP_PRIVATE_STORAGE_PATH sebelum deployment. Simpan release
sebelumnya sampai release baru terbukti stabil. Untuk rollback, kembalikan release
sebelumnya dan konfigurasi environment yang cocok sesuai prosedur perubahan. Jangan
menghapus data baru tanpa rencana pemulihan database.

Jangan menyimpan .env, password, API key, credential Drive, private key, log,
database dump, atau backup di webroot atau Git. Jangan menggunakan credential Docker
development, IP container Docker, atau development encryption key di production.
Private storage dan log harus berada di luar webroot. Hanya uploads/profil yang boleh
diekspos, dengan aturan web server yang membatasi format dan menolak executable.

KONTEKS DEVELOPMENT LOKAL SAJA
===============================

Runner berada di root repository pada run-local-php.sh. Subbagian ini hanya untuk
memahami perilaku development lokal dan bukan instruksi deployment production.

Runner memuat .env lokal bila tersedia, mengisi default development, lalu menjalankan
php -S 127.0.0.1:8000. Sebelum start, runner memakai mkdir -p untuk membuat kategori
private audit_evidence, bukti_auditor, instrumen, penetapan, ppepp_documents,
rtm_photos, spmi_source, tmp, dan user_photos di bawah APP_PRIVATE_STORAGE_PATH.
Runner juga membuat profil di bawah APP_PUBLIC_UPLOADS_PATH serta
application/cache/sessions.

mkdir -p adalah perilaku runner lokal, bukan perilaku production. Perintah itu
membuat parent yang diperlukan, mempertahankan direktori yang sudah ada, tidak
menghapus atau mengosongkan file, dan gagal jika path yang seharusnya menjadi
direktori ditempati file. Pada production, tim deployment harus membuat direktori,
ownership, dan mode secara eksplisit seperti bagian STRUKTUR DIREKTORI PRODUKSI.

JANGAN menjalankan run-local-php.sh di production. Jangan menjadikan php -S sebagai
service, process manager, atau endpoint publik. Referensi lokal ini tidak mengubah
persyaratan PHP-FPM dan web server production.

DOKUMENTASI RUJUKAN
===================

Gunakan docs/DEPLOYMENT_NON_DOCKER.md sebagai panduan canonical untuk konfigurasi
server, PHP-FPM, Nginx atau Apache, public uploads, permissions, dan upgrade manual.
Gunakan .env.example hanya sebagai daftar nama environment variable dan contoh
placeholder, bukan sebagai tempat menyimpan secret production.
