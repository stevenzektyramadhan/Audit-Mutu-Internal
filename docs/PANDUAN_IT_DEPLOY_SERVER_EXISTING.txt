PANDUAN DEPLOYMENT AMI (NATIVE ALMALINUX DARI ZIP)
Target: Server AlmaLinux yang SUDAH BERJALAN (Multi-Project)

Perhatian untuk Tim IT:
- Server ini sudah ada project lain. JANGAN reset/restart service global sembarangan.
- JANGAN ubah konfigurasi global Nginx/PHP-FPM yang dipakai project lain.
- Cukup tambah 1 server block Nginx baru dan arahkan ke pool PHP-FPM yang sesuai.
- Aplikasi ini TIDAK butuh Git, Docker, Composer, atau file .env di server.

================================================================================
RINGKASAN LOKASI & FAKTA
================================================================================
1. Folder aplikasi disarankan: /var/www/html/ami
2. Hanya ada TIGA (3) file konfigurasi yang perlu diedit Tim IT:
   - application/config/production/config.php
   - application/config/production/database.php
   - application/config/production/ami.php
3. index.php SUDAH diset production. JANGAN diedit.
4. Database: Gunakan database baru khusus project ini (misal: ami).
   JANGAN sentuh database project lain.

================================================================================
LANGKAH 1: EKSTRAK FILE ZIP
================================================================================
1. Upload file AMI-NATIVE-ALMALINUX-<versi>.zip ke server.
2. Buat folder target dan ekstrak:
   sudo mkdir -p /var/www/html/ami
   sudo unzip -q AMI-NATIVE-ALMALINUX-<versi>.zip -d /tmp/ami_extract
   
   # Pastikan index.php berada langsung di root /var/www/html/ami/
   sudo cp -r /tmp/ami_extract/AMI/* /var/www/html/ami/
   rm -rf /tmp/ami_extract

================================================================================
LANGKAH 2: CEK USER PHP-FPM & ATUR PERMISSION
================================================================================
Karena server sudah ada project lain, cek user yang menjalankan PHP-FPM saat ini:
   ps -eo user,group,comm | grep -E 'php-fpm|php-cgi' | head -n 5

(Biasanya user: "apache" atau "nginx")

Jalankan perintah ini (ganti <user> dan <group> sesuai hasil di atas):
   # 1. Kepemilikan kode (read-only untuk web server)
   sudo chown -R root:<group> /var/www/html/ami
   sudo find /var/www/html/ami -type d -exec chmod 0755 {} +
   sudo find /var/www/html/ami -type f -exec chmod 0644 {} +

   # 2. Folder yang WAJIB bisa ditulis aplikasi (Upload, Cache, Log, Session)
   sudo chown -R <user>:<group> /var/www/html/ami/uploads
   sudo chown -R <user>:<group> /var/www/html/ami/application/cache
   sudo chown -R <user>:<group> /var/www/html/ami/application/logs

   sudo find /var/www/html/ami/uploads -type d -exec chmod 0775 {} +
   sudo find /var/www/html/ami/uploads -type f -exec chmod 0664 {} +
   sudo find /var/www/html/ami/application/cache -type d -exec chmod 0775 {} +
   sudo find /var/www/html/ami/application/logs -type d -exec chmod 0775 {} +

   # 3. SELinux (Wajib di AlmaLinux jika SELinux Enforcing)
   if [ "$(getenforce 2>/dev/null)" = "Enforcing" ]; then
       sudo semanage fcontext -a -t httpd_sys_rw_content_t '/var/www/html/ami/uploads(/.*)?'
       sudo semanage fcontext -a -t httpd_sys_rw_content_t '/var/www/html/ami/application/cache(/.*)?'
       sudo semanage fcontext -a -t httpd_sys_rw_content_t '/var/www/html/ami/application/logs(/.*)?'
       sudo restorecon -Rv /var/www/html/ami/uploads /var/www/html/ami/application/cache /var/www/html/ami/application/logs
   fi

================================================================================
LANGKAH 3: SETUP DATABASE
================================================================================
Buat database dan user baru khusus untuk AMI di MariaDB/MySQL:
   mysql -u root -p

   CREATE DATABASE ami CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'ami_user'@'localhost' IDENTIFIED BY 'PASSWORD_KUAT_DATABASE';
   GRANT ALL PRIVILEGES ON ami.* TO 'ami_user'@'localhost';
   FLUSH PRIVILEGES;
   EXIT;

PILIH SALAH SATU OPSI IMPORT (JANGAN DUA-DUANYA):

OPSI A (Rekomendasi - Pakai database_init.sql):
File ini sudah berisi skema lengkap terbaru + 1 akun Super Admin bawaan.
   mysql -u ami_user -p ami < /var/www/html/ami/database_init.sql
   (Setelah import, langsung lanjut ke Langkah 4. Saat login pertama kali,
   sistem akan meminta ganti password).

OPSI B (Pakai database_schema.sql):
Jika ingin membuat akun Super Admin dengan email/password sendiri via CLI:
   mysql -u ami_user -p ami < /var/www/html/ami/database_schema.sql
   php /var/www/html/ami/scripts/bootstrap_super_admin.php
   (Input email & password admin sesuai prompt terminal).

================================================================================
LANGKAH 4: EDIT 3 FILE KONFIGURASI
================================================================================
Masuk ke folder: /var/www/html/ami/application/config/production/

1. File: config.php
   Perintah: nano config.php
   Bagian yang wajib diubah:
   - $config['base_url'] = 'https://subdomain.domain-kampus.ac.id/';  // Wajib HTTPS & akhiri slash '/'
   - $config['encryption_key'] = 'GENERATE_RANDOM_STRING_MINIMAL_32_KARAKTER';
   - $config['sess_save_path'] = APPPATH . 'cache/sessions';
   - $config['log_path'] = APPPATH . 'logs/';
   - $config['cookie_secure'] = TRUE; // Pastikan TRUE karena menggunakan HTTPS

2. File: database.php
   Perintah: nano database.php
   Bagian yang wajib diubah:
   - 'hostname' => 'localhost',
   - 'username' => 'ami_user',
   - 'password' => 'PASSWORD_KUAT_DATABASE',
   - 'database' => 'ami',

3. File: ami.php
   Perintah: nano ami.php
   Secara default sudah terisi:
   - 'private_storage_path' => FCPATH . 'uploads/',
   - 'public_uploads_path'  => FCPATH . 'uploads/',
   (Biarkan default kecuali IT ingin memindahkan folder upload ke partisi lain).

================================================================================
LANGKAH 5: KONFIGURASI NGINX (TAMBAH VHOST BARU)
================================================================================
JANGAN edit nginx.conf utama. Buat file server block baru di:
/etc/nginx/conf.d/ami.conf

Contoh isi /etc/nginx/conf.d/ami.conf:

server {
    listen 80;
    server_name ami.domain-kampus.ac.id;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name ami.domain-kampus.ac.id;

    root /var/www/html/ami;
    index index.php;

    # Sesuaikan path sertifikat SSL server Anda:
    ssl_certificate /etc/pki/tls/certs/ami.crt;
    ssl_certificate_key /etc/pki/tls/private/ami.key;

    client_max_body_size 20M;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    # Teruskan request PHP ke PHP-FPM socket/port yang sedang aktif di server
    location ~ \.php$ {
        try_files $uri =404;
        include fastcgi_params;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
        # Sesuaikan dengan socket PHP-FPM aktif di server Anda:
        # fastcgi_pass unix:/run/php-fpm/www.sock;
        # atau jika pakai port:
        # fastcgi_pass 127.0.0.1:9000;
        fastcgi_pass unix:/run/php-fpm/www.sock;
    }

    # KEAMANAN: Blokir akses langsung via web ke folder private dan system
    location ~ ^/(application|system|vendor|\.git|uploads/(audit_evidence|bukti_auditor|instrumen|penetapan|ppepp_documents|rtm_photos|spmi_source|tmp|user_photos))(/|$) {
        deny all;
        return 404;
    }

    # KEAMANAN: Blokir eksekusi script PHP di dalam folder uploads
    location ~ ^/uploads/.*\.php$ {
        deny all;
        return 404;
    }
}

Test konfigurasi Nginx lalu reload:
   sudo nginx -t
   sudo systemctl reload nginx
